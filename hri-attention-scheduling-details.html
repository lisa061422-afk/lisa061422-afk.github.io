Human–Multi-Robot Collaboration

Human-Attention Scheduling for Multi-Robot Supervision

This project develops an optimization-based recommendation system for allocating limited human attention among multiple robots facing time-critical obstacle-avoidance tasks. The system determines which robot should receive attention and when, and was evaluated in a controlled study with 40 human participants.

Paper Poster

Task model

Operator interventions are modeled as obstacle-avoidance tasks with release times, service times, and deadlines.

Scheduling method

Decision-tree search determines which robot should receive the limited human-attention resource and when.

Evaluation

The resulting attention-guided recommendation system was evaluated in a controlled study with 40 human participants.

My Contribution

Real-Time Human-Attention Scheduling

Within the broader recommendation-system project, I developed the real-time scheduling methodology. My work modeled operator interventions as deadline-constrained tasks, used receding-horizon decision-tree search to optimize which robot should receive attention and when, and converted the resulting schedule into timed recommendations for the operator.

System Model

From Obstacle Encounters to Attention Tasks

An approaching obstacle creates a task for its robot. The task must receive a short interval of human control before the obstacle reaches the collision point; simultaneous requests create contention for the operator's attention.

Release time
\(\alpha_{n,j}\): the instant obstacle task \(j\) becomes active for robot \(n\).
Deadline
\(d_{n,j}=\alpha_{n,j}+\Delta\): the latest completion time that avoids the collision.
Service time
\(c_{n,j}\): the required human-control time; the evaluated scheduling scenario uses 2 seconds per task.
Priority cost
Missed stone, tree, and pond tasks incur costs 10, 5, and 2, respectively.

Cost Function and Constraints

Prioritize the Most Consequential Tasks

The implementation stores collision scores \((-10,-5,-2)\) for stone, tree, and pond tasks and maximizes the accumulated score. The positive-cost expression below is the equivalent minimization form used to explain the schedule.

Collision-weighted scheduling objective

\[ \min_{\pi\in\mathcal{F}} J(\pi)=\sum_{n=1}^{N}\sum_j w_{q_{n,j}}\,\delta_{n,j}(\pi), \qquad (w_{\mathrm{stone}},w_{\mathrm{tree}},w_{\mathrm{pond}})=(10,5,2). \]

Here \(\delta_{n,j}(\pi)=1\) when schedule \(\pi\) misses the task deadline and is zero otherwise. When all requests cannot be served, the schedule favors decisions that avoid the largest collision penalties.

Single shared resource
\(u_n(t)\in\{0,1\}\) and \(\sum_{n=1}^{N}u_n(t)\leq 1\): the operator controls at most one robot at a time.
Release-time feasibility
\(\beta_{n,j}\geq\alpha_{n,j}\): service cannot begin before the obstacle task appears.
Deadline feasibility
\(\beta_{n,j}+c_{n,j}\leq d_{n,j}\): a selected intervention must finish before collision.
Available-task test
At decision time \(t\), robot \(n\) is a feasible choice only when \(t+r_{n,j}(t)\leq d_{n,j}\), where \(r_{n,j}\) is the remaining service time.

Scheduling Example

Why the Attention Order Matters

Simultaneous tasks can have different deadlines and collision costs. Serving requests in arrival order can miss a high-cost task, whereas cost-aware scheduling chooses an order that limits the total penalty.

Receding-Horizon Prediction

Search Ahead, Apply One Decision, Then Replan

Contending tasks are evaluated over a finite future window. The implementation searches the feasible decision tree over a 100-second prediction horizon, applies only the first action from the best branch, and repeats the process at the next contention event.

  1. Step 1 Release tasks

    Obstacle encounters activate attention requests for one or more robots.

  2. Step 2 Detect contention

    Prediction is triggered when at least two active tasks compete for the operator.

  3. Step 3 Expand decisions

    Feasible robot choices are branched forward while tracking service and deadline states.

  4. Step 4 Score branches

    Candidate schedules are ranked by their accumulated collision penalties.

  5. Step 5 Apply and replan

    Only the first selected assignment is executed before the horizon is rebuilt.

Rolling decision

\[ \pi^{\star}(t)=\arg\min_{\pi\in\mathcal{F}(t,t+T_p)}J_{t:t+T_p}(\pi), \qquad u(t)=\operatorname{first}\!\left(\pi^{\star}(t)\right). \]

This is model-predictive task scheduling: the optimized object is the attention assignment, not a continuous-state motion controller.

Recommendation Generation

Convert the Schedule into Timed Prompts

The selected operator-usage trace is transformed into recommendation pairs \((t_k,n_k)\), where \(t_k\) is the reminder time and \(n_k\) identifies the robot that should receive attention. Idle entries are removed, repeated assignments close in time are merged, and incomplete service intervals are filtered before the recommendation sequence is sent to the interface.
